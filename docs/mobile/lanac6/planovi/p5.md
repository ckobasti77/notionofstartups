### Izmena 1 — backend: `movePage` sme u drugu oblast POD stranicu (C10, temelj)

**Fajl:** `packages/backend/convex/areasV2.ts:3732-3736`.

**Zašto:** to je jedina prepreka za cilj faze. Danas ta grana baca. Zamenjuje je
kompozicija dve **postojeće** funkcije, u istoj transakciji:

```ts
if (targetParent !== null) {
  // 1) cela grana se seli u koren ciljne oblasti (sidecars: ivice, viewport,
  //    relacije, pending zahtevi — sve rešava postojeći helper)
  await movePageAcrossAreasWithSidecars(ctx, {
    page, targetAreaId: args.targetAreaId, actorProfileId: profile._id, now,
  });
  // 2) ZAMKA: `page` je sada USTAJAO dokument (helper je patch-ovao areaId i
  //    parentPageId). `moveWithinArea` čita `child.areaId` za kapacitet i za
  //    `getAvailableCanvasPosition` — sa starim dokumentom bi kartica sletela u
  //    STARU oblast. Zato OBAVEZNO ponovno čitanje:
  const moved = await ctx.db.get("pages", page._id);
  if (moved === null) throw new Error("Stranica nije pronađena posle premeštanja.");
  return await moveWithinArea(ctx, {
    child: moved, targetParent, actorProfileId: profile._id, now,
  });
}
```

`now` se izračuna jednom (`const now = Date.now()`) i deli oba koraka.

**Šta se time dobija:**
- `targetParent` je već proveren da živi u `targetAreaId` (`:3717-3720`) — cilj ne
  može da bude stranica iz treće oblasti.
- Vlasništvo: `movePageAcrossAreasWithSidecars` odbija granu sa tuđim stranicama
  (`:3358-3369`); `moveWithinArea` sam odlučuje da li je ugnježdavanje pod TUĐU
  stranicu direktno ili ide na odobrenje (`:1117-1148`).
- Ciklus i dubina: `assertReparentDepth` (`:1149-1151`) — nepromenjeno.
- Aktivnost se beleži jednom (`applySameAreaReparent` ne zove `recordActivity`;
  provereno `:696-761`).

**Semantika koju treba znati i saopštiti korisniku:** kad je ciljni roditelj TUĐ,
rezultat je `nestingStatus: "pending"` — a stranica je **već promenila oblast** i
stoji u njenom korenu. To nije bug nego posledica dvokoraka; UI to mora reći
doslovno (Izmena 4).

**Testovi (obavezni, `packages/backend/convex/areasV2.test.ts`,** seed
`seedAreasV2Workspace` već daje `areaA1`/`areaA2` u istom startupu):

1. `"premeštanje u drugu oblast pod svoju stranicu sleti tačno tamo"` — `asActor`
   pravi `parent` u `areaA2` i `child` u `areaA1`; `movePage({child, areaA2, parent})`
   → `nestingStatus === "none"`; `ctx.db.get("pages", child)` ima
   `areaId === areaA2` **i** `parentPageId === parent`; placement postoji sa
   `rootPageId === parent` (indeks `by_pageId`).
2. `"premeštanje pod TUĐU stranicu u drugoj oblasti seli oblast i traži odobrenje"` —
   `asMember` pravi `parent` u `areaA2`, `asActor` `child` u `areaA1`; actor zove
   `movePage` → `nestingStatus === "pending"`, `requestId !== null`; dokument ima
   `areaId === areaA2`, `parentPageId === null`.
3. (jeftino, poželjno) `"roditelj iz treće oblasti se odbija"` — `movePage` sa
   `targetAreaId: areaA2` i roditeljem iz `areaA1` → `rejects.toThrow()`.

**Ne postoji test koji tvrdi da ta grana baca** — provereno grepom po
`areasV2.test.ts` (svi `movePage` pozivi sa `targetParentPageId: null`, osim
`:1652-1658` koji je ISTA oblast + potomak → i dalje baca „kružnu"). Dakle ništa
se ne kvari.

**LANAC UVOZA:** `areasV2.movePage` ← `useMutation(api.areasV2.movePage)` u
`page-actions-sheet.tsx:85` (postoji) i u `undo-bar.tsx` (Izmena 2) ←
`<PageActionsSheet>` na `stranica/[id].tsx:104` i `zadatak/[id].tsx:339` ←
ekran „Stranica"/„Zadatak" → „…" → „Premesti u oblast".

### Izmena 2 — `pageReparent` član trake „Poništi" (temelj za C9/C10)

**Fajlovi:** `apps/mobile/src/lib/undo.ts`, `apps/mobile/src/components/undo-bar.tsx`.

**Zašto:** premeštanje i ugnježdavanje su upisi u bazu, a pravilo lanca je da svaki
upis ima „Poništi". Danas ga nemaju.

```ts
| {
    kind: 'pageReparent';
    startupId: Id<'startups'>;
    pageId: Id<'pages'>;
    /** Oblast PRE radnje. */ targetAreaId: Id<'startupAreas'>;
    /** Roditelj PRE radnje (null = koren oblasti). */
    targetParentPageId: Id<'pages'> | null;
  }
```

`undo-bar.tsx`: `const movePage = useMutation(api.areasV2.movePage)` i
`case 'pageReparent': await movePage({...action}); return;`

**Ime je namerno `pageReparent`, ne `pageMove`** — `pageMove` (`undo.ts:42-49`) VEĆ
postoji i znači koordinate kartice na kanvasu. Dva slična imena za dve različite
stvari su tačno ona greška koju lanac 4 opisuje kod `edgeKind`.

**Iskrena granica (upisuje se kao komentar uz član):** inverz vraća **mesto**
(oblast + roditelj), ne i sve što je selidba usput arhivirala — `movePage` preko
granice oblasti arhivira canvas ivice grane (`areasV2.ts:3597-3618`) i daje kartici
novu slobodnu poziciju. Poništavanje vraća stranicu tamo gde je bila, ivice ne.
Isto važi i za desktop; nema mutacije koja to vraća.

**LANAC UVOZA:** `lib/undo.ts` → `undo-bar.tsx:104-331` (`restore`) →
`<UndoBar/>` na `stranica/[id].tsx:113` i `zadatak/[id].tsx:348` → traka se pojavi
odmah posle premeštanja, na istom ekranu (sheet se zatvori, ekran ostaje).
